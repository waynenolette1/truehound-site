MCP hooks and Truehound in Claude

Last compared with the product's code 25 October 2026.

Two separate things share the MCP name. An MCP hook runs in your developers' AI clients and asks Truehound allow, ask or deny before each tool call. The MCP server lets Claude and other assistants read your access data and file requests in Truehound, under the same approvals as a person.

What you need, and what is not on yet

Both need a team workspace. The hook is an open script that needs Node 18 or newer. Drafting hook policies with Claude needs your own Anthropic key, and without one the drafts come from rules. The endpoint is the address shown on your workspace's Developers page.

MCP hooks: govern calls without a gateway

A small open script runs in the agent client before each tool call. It sends one small request to your workspace and turns the answer into the client's own hook output. Nothing is rerouted: the tool call still goes from the client straight to the MCP server. Read every line of the script before you install it.

Supported clients: Claude Code, Cursor, Windsurf, VS Code Copilot (preview) and Codex CLI, each through its own documented hook.

Install the hook

  1. Step 1. Create a hook token

    On AI agents, MCP hooks, create a token for the workspace, or one per person so every call is tied to that person. It is shown once.

  2. Step 2. Run the install command on each laptop

    The page shows a command for your client that downloads the script and installs it. It reads the token from an environment variable, writes it to a file only the user can read, and adds the hook to the client's user config. Running it again updates it and never adds a second entry.

    For managed laptops, print the client config and deploy it by MDM instead.

What the hook sends, and how it behaves

  • A summary of the tool input, at most 2,000 characters, with secrets replaced by [REDACTED] on the laptop first. The server redacts again before it stores anything.
  • The request is abandoned after 250 milliseconds. An allow is cached for the time your workspace sets (60 seconds by default), so a repeated call makes no request.
  • If Truehound is unreachable, your workspace's fail mode decides. Open, the default, lets the call run and keeps a record to send next time. Closed denies it. A policy can set its own.
  • The option for all tools also checks built-in tools such as shell commands. The browser option also checks the client's own web fetch and search, so an agent's browsing is governed by site.

The hook cannot see a person driving a browser, or an agent that drives a browser with no tool call through the client. The Truehound browser extension does not observe agent browser actions.

Policies and evidence

  • Policies allow, ask or deny by MCP server, tool, user, group or an input pattern, with a monitor mode that records without blocking.
  • Every MCP server seen is listed, approved or not (shadow MCP), and you approve one in a click.
  • Policies can be drafted from your last 30 days of history, by Claude on your own key or by rules, with each rule's impact before you apply it.
  • Every call is kept redacted for the retention you set (365 days by default), measured latency is shown, and the calls export as CSV.

Truehound in Claude: the MCP server

Truehound serves a remote MCP server (Streamable HTTP, JSON-RPC) at the /mcp path of your API address. Anyone in the workspace can make a token for themselves. A token can be read only, and can expire after 1 to 365 days. Claude and other MCP clients can also sign in with OAuth 2.1, with a consent page, short-lived access tokens and refresh tokens that rotate. An admin sets token lifetimes and the client hosts that are allowed.

Tools include who_has_access, find_person, list_leavers, offboard_person, proposal_status, list_access_requests, approve_request, deny_request, cancel_request, review_status, decide_review_rows, start_review, list_unused_licenses, open_ticket and change_role. The Developers page lists every tool and whether it reads or files something.

Writes never change an app directly. A removal or role change files a proposal that people approve under your approval policy, a decision is made as the token's person under the same policy, and nobody can approve their own request. A reviewer decides only their own rows. Every call is sealed in Proof.

Terraform provider

Last compared with the product's code 25 October 2026.

Review schedules, the approval policy, role bundles and webhooks are the parts of a Truehound workspace that belong in code review. The provider manages them through the public API, so a change to who approves a fix goes through a pull request like any other change.

What you need, and what is not on yet

The provider is not on the Terraform Registry yet, so you cannot install it with a plain terraform init today. It has been applied against the production API, and a second plan found no drift. For a build of the provider, email truehoundhq@truehound.io. It needs a team workspace and an API key.

On this page

  1. What it manages
  2. Configure it
  3. Drift and import

What it manages

  • truehound_review_schedule: a recurring access review, with cadence, systems, reviewers, due days, full or delta mode, and what happens at the due date.
  • truehound_approval_policy: the one approval policy per workspace. Destroying it resets the default.
  • truehound_role_bundle: a named set of system and role grants.
  • truehound_webhook: a signed webhook endpoint. The signing secret is kept in state as a sensitive value.
  • truehound_webhook_events (data source): every webhook event type.

Configure it

  1. Step 1. Make an API key

    In Developers, API keys, make a key with the config:read, config:write, webhooks:read and webhooks:write scopes. See API and webhooks.

  2. Step 2. Point the provider at your workspace

    Set TRUEHOUND_API_KEY, and TRUEHOUND_ENDPOINT to the API address your workspace shows. The provider defaults to api.truehound.io, which is not live yet.

Drift and import

Terraform reads each object back from the API, so a change made in the app shows as drift in the next plan. Existing schedules, roles and webhooks can be imported. A schedule that Terraform manages is launched by the same server cron as one made in the app.

Change history on every configuration object shows who changed it and when.

The provider creates and deletes real objects and can reset the approval policy. Try it in a test workspace first.

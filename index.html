Security and trust

Built to be trusted with the keys.

A tool that can see who has access has to be careful with it. Here is exactly what Truehound keeps, where, and for how long.

SecurityPrivacyAI disclosure

  • Your tokens stay with you

    The scan runs in your browser and talks to GitHub directly. Your token is kept for this session unless you choose to remember it. Search goes through our relay, which never stores or logs it.

  • Read-only by default

    A token with read access is enough for the whole audit. A fix needs write access for that one change, and the app checks before it tries.

  • Nothing changes without you

    Every removal waits for a person to confirm it. Truehound never decides someone left: your HR system, identity provider or your own list does.

  • Proof you can check

    Every scan and every change is sealed in a SHA-256 hash chain. Verify it yourself on the Proof page, and export it with the report.

  • Clear data retention

    Results are kept in your browser, not on our servers. Reset or sign out, and they are gone.

  • Secrets stay secret

    A secret found in code is shown as its file, line and a masked preview. The value is never stored or sent anywhere.

FAQ

Before you paste a token.

Something else? A person reads every email to truehoundhq@truehound.io.

Does my GitHub token leave my browser?
Almost never. The audit runs in your browser and talks to GitHub directly. The one exception is search: GitHub blocks code and commit search from browsers, so those requests pass through our relay, which forwards your token to GitHub and never stores or logs it. Use a token from an org owner: a fine-grained token with read access to Members, Administration and Contents is enough for the audit; a fix needs write access for that one change, and the app checks before it tries. Any secret we find is shown as the file, the line and a masked preview; we never store or send the value.
How do you know who left?
You tell us. Paste names, work emails or GitHub handles, or upload a CSV from HR. We only call someone departed if they are on that list or you mark them. People with write access and no activity in 90 days are shown as “possibly left: confirm”, never as gone.
What can it change on GitHub?
Four things, each only after you confirm and only if your token is allowed: remove someone from the org, change an owner to a member, remove an outside collaborator, delete a deploy key. Every change is recorded in a tamper-evident log you can export.

Is this a full security program?
No. Truehound checks the access GitHub shows it. It is not a substitute for a full security program and it does not prevent every breach. It closes the gap that the cases above came through: access nobody took back.
Can I use the report for a SOC 2 access review?
The report lists everyone with access, their role and two-factor status, every finding, and every change you made with its sealed record, dated. It is evidence for an access review; your auditor decides what it covers.

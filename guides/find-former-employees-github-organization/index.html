How to find former employees still in your GitHub organization

Sources checked 22 October 2026. 6 minute read.

The short answer

Export three lists from GitHub: organization members, outside collaborators and pending invitations. Match each GitHub username to a real person using verified domain emails or, if SAML single sign-on is on, the linked SAML identity, and compare that against your HR or identity provider list of leavers. Anyone who left but still appears is a removal. GitHub usernames rarely match real names, so the matching step is where most leavers slip through.

Why leavers stay in GitHub

A GitHub account belongs to the person, not to your company. Turning off someone's work email or identity provider account does not remove their personal GitHub account from your organization. Only with Enterprise Managed Users does your identity provider own the account and its organization membership, provisioned through SCIM. So the organization keeps a list of people that nobody reconciles.

The other reason is naming. The People tab shows usernames such as octocat, not legal names, so a leaver is easy to miss by eye.[14],[13]

Export everyone who has access

  1. Step 1. Export the member list[1]

    Go to your organization, open the People tab, and use the Export dropdown next to the search bar to download a CSV or JSON file. The report includes each username and display name, whether two-factor authentication is on, and whether the person is an owner or a member.

  2. Step 2. List outside collaborators[3],[15]

    Outside collaborators are not members, so they are not in the member export. On the People tab, open Outside collaborators in the sidebar. With the API, GET /orgs/{org}/outside_collaborators returns them, and filter=2fa_disabled narrows the list to those without two-factor authentication.

  3. Step 3. List pending invitations[4],[5],[2]

    On the People tab, Invitations shows member invites and Pending collaborators shows outside collaborator invites. An open invite sent to a leaver's address can still be accepted, so it belongs on your list. GET /orgs/{org}/invitations returns pending member invitations and GET /orgs/{org}/failed_invitations shows ones that failed.

  4. Step 4. Or pull all three with the GitHub CLI[6],[2]

    The gh api command calls any REST endpoint with your login and follows every page with --paginate. For example: gh api --paginate orgs/YOUR-ORG/members --jq '.[].login'. Swap members for outside_collaborators or invitations to get the other two lists. GET /orgs/{org}/members also takes role=admin to list only owners.

Match usernames to real people

Your leaver list has names and work emails. GitHub has usernames. You need a bridge between the two.

  • Verified domain emails: if you verify your company domain and your organization has agreed to the GitHub Customer Agreement, owners can see each member's email address on that domain. In GraphQL, the organizationVerifiedDomainEmails field on a user returns their verified addresses that match the organization's verified domains.
  • SAML identities: with SAML single sign-on on GitHub Enterprise Cloud, open People, select a member, and open SAML identity linked to see the identity from your identity provider. To do this in bulk, query the organization's samlIdentityProvider in GraphQL; its externalIdentities connection lists the identities your provider linked. Organization owners can read it, including with a classic token that has the read:org scope.
  • No SSO and no verified domain: match by hand using the display name, profile and commit email, and ask each team lead to confirm the usernames on their team. Write down how each match was made.[7],[8],[10],[9]

A personal email on a GitHub account does not prove who the person is. When a match is a guess, confirm it with the person's manager before you remove anyone.

Check last activity before you act

  • Audit log: organization owners can open Settings, then Logs, then Audit log, and search by actor:USERNAME to see what an account did. The log holds the last 180 days, and the view shows three months unless you add a created: date range. You can export it as CSV or JSON.
  • Dormant users report: on GitHub Enterprise Cloud, the enterprise Compliance page can generate a Dormant Users report. An account counts as dormant after 30 days with no qualifying activity, and that covers outside collaborators too.
  • Read dormancy carefully. GitHub says access with a personal access token, SSH key or GitHub App, and Git operations on private repositories, do not count as activity. A quiet account may still be pulling code.
  • The audit log API is only for organizations on GitHub Enterprise Cloud. On other plans, use the web view and its export.[11],[12]

Remove the leavers and what they could reach

For each confirmed leaver, remove the member from the organization, remove the outside collaborator from all repositories, and cancel any pending invitation. GitHub keeps a removed member's data for three months in case you reinstate them. The step by step is in /guides/remove-user-from-github-organization.

Then deal with what removal does not touch: deploy keys, Actions secrets and personal access tokens the person could have used. See /guides/rotate-github-deploy-keys. Record each removal with its date; your auditor will want it, and the checklist at /tools/offboarding-checklist covers the other apps.[14],[15]

Questions

Does disabling someone in Okta or Google remove them from GitHub?
Not by itself. A normal GitHub account belongs to the person, and they stay on the member list until you remove them. With Enterprise Managed Users, your identity provider owns the account and its membership, so offboarding there does carry through.
Can I see members' work email addresses?
Yes, if you verify your company domain and your organization has agreed to the GitHub Customer Agreement. Owners can then see each member's email on that domain.
Is a dormant account safe to leave?
No. GitHub does not count token, SSH key or private repository Git activity toward dormancy, so a dormant account may still be in use. Match it to a person and decide.
Are outside collaborators in the member export?
GitHub's member export page lists member fields only. List outside collaborators separately from the People tab or the API.
How far back can I see what a leaver did?
The organization audit log holds 180 days. Export it if you need a longer record.

Okta deactivate user: what it removes and what it leaves behind

Sources checked 22 October 2026. 5 minute read.

The short answer

Deactivating a user in Okta stops all their active Okta sessions, revokes their app assignments and admin roles, and blocks new sign-ins. The account in each app is only deactivated where that app has provisioning with Deactivate Users turned on. Apps people sign in to directly, local passwords, and keys or tokens created inside other apps are not touched, so they need their own offboarding.

What deactivation does in Okta

  • The user can no longer create sessions, and all their active sessions in Okta are stopped.
  • Their app assignments are revoked, so they can no longer reach their assigned apps through Okta.
  • Their admin roles are revoked and they are unassigned from the Okta Admin app.
  • Okta API tokens the user created are deprovisioned at the same time, because those tokens act with the creating admin's privileges. Integrations that used them will stop working.
  • Deactivation runs as a background task; large batches can take a while. The user's status becomes DEPROVISIONED when it finishes.[1],[6],[7]

When apps actually lose the account

Removing the assignment in Okta stops single sign-on into the app. Whether the account inside the app is also deactivated depends on provisioning. Okta deprovisions the user from assigned apps only where deprovisioning is enabled for that app, and skips inactive apps.

For apps with provisioning, open the app under Applications, go to the Provisioning tab, choose To App, and enable Deactivate Users. Okta then deactivates the person's account in that app when they are unassigned or deactivated in Okta. For apps that need manual deprovisioning, Okta puts a notice on the admin dashboard instead.[1],[3],[4],[5]

Turning on Deactivate Users is not retroactive. It only applies to deactivations and unassignments after you enable it, so people deactivated earlier may still have live accounts in that app.

What deactivation does not touch

  • Apps people sign in to with a local password rather than through Okta. Deactivating the Okta user does nothing there.
  • Apps with only single sign-on, no provisioning: the person loses the Okta route in, but the account in the app stays until someone removes it.
  • Keys and tokens created inside other systems. A GitHub deploy key, for example, belongs to the repository and stays active after the person who added it is removed. See /guides/rotate-github-deploy-keys.
  • Group memberships in Okta. Deactivated users are not removed from groups; that only happens on deletion.
  • Authentication factors and the user's data in Okta, which are removed only when the user is deleted.[1],[4],[8]

Suspend, deactivate or delete

  • Suspend: for a leave of absence or a paused contractor. Suspended users cannot sign in to Okta, and their app and group memberships are kept and reinstated when you unsuspend them. Only active users can be suspended.
  • Deactivate: for someone who has left. Sessions end and app assignments and admin roles are revoked. Okta's API reference calls deactivation a destructive operation, so be sure before you run it.
  • Delete: permanent, and you cannot undo it. A user must be deactivated before they can be deleted. Deletion removes factors, group memberships, linked objects and the user's data in Universal Directory, frees the username for reuse, and Okta starts permanent deletion of customer data within 30 days.[2],[7],[1]

Deactivate a user in the Admin Console

  1. Step 1. Check privileged access and service tokens first[1],[6]

    If the user is managed with Okta Privileged Access, end that first. If they created API tokens your integrations rely on, create replacements from a service account before you deactivate, since Okta recommends service accounts for API tokens.

  2. Step 2. Deactivate[1]

    In the Admin Console, go to Directory, then People, then More Actions, then Deactivate. Select the users, choose Deactivate Selected, and confirm.

  3. Step 3. Clean up the apps Okta did not reach

    List the apps the person used that have no provisioning or use direct logins, and remove the account in each. The checklist at /tools/offboarding-checklist builds that list for your apps.

Questions

Does deactivating a user in Okta remove them from all apps?
It removes their Okta assignments and access through Okta. The account inside each app is only deactivated where provisioning with Deactivate Users is set up.
Can I reactivate a deactivated user?
Yes. Reactivating restores the account, but you may need to reassign some apps. Group rules can do that for you.
What happens to Okta API tokens the person created?
They are deprovisioned when the user is deactivated. Create integration tokens from a service account so this does not break anything.
Should I suspend or deactivate a leaver?
Deactivate. Suspension keeps app and group memberships so the person can come back, which is meant for leave or temporary pauses.
Why is a deactivated user still in an app?
The app has no provisioning, Deactivate Users is off, the app is inactive in Okta, or the person was deactivated before you enabled the setting.

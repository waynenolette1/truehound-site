Accessibility

Accessibility conformance report

Truehound against WCAG 2.1 level A and AA, as of 23 October 2026. It says what was tested, how, and what was not. It is a self-assessment, not an audit.

Summary

Product
Truehound, truehound.io: the website, the free scan and the live demo
Standard
WCAG 2.1, level A and AA (the 50 success criteria below)
Report date
23 October 2026
Results
26 Supports, 0 Does not support, 7 Not applicable, 17 Not evaluated
Contact
truehoundhq@truehound.io

What Supports means here. No failure was found by the method named in the Basis column. It does not mean a person using assistive technology has confirmed it. Where no method checks a criterion, the result is Not evaluated, never Supports. The report was not audited by an independent firm.

What was tested

  • Home, pricing, the free scan entry, and the two sign-up dialogs
  • Trust Center, sub-processors, sub-processor changes, status, roadmap and this report
  • Comparison pages (every vendor), the total cost comparison, tools, calculators, tours and guides
  • The live demo: home, findings, Everyone, Left and still has access, Sources, Review and campaigns, Posture, Controls, Workflows, Discovery, Operations, Requests, Lifecycle, Workspaces, agent, assistant, AI and the developer console
  • The payment-locked screen

How it was tested

  • axe. axe-core 4.11.4 with the WCAG 2.0 and 2.1 level A and AA rule sets, run in a real browser at 1440 and 390 pixels wide. Our build checks fail on any serious or critical finding.
  • script. Scripted browser checks that axe cannot make: reflow at 320 CSS pixels, a Tab walk of 13 pages looking for traps and for a visible focus indicator on every stop, and a main landmark on each.
  • e2e. The page's own end-to-end test, for example the tours with the arrow keys and the form error messages.
  • review. A developer read the page against the criterion. No tool was used.

Known gaps

  • No person using a screen reader, voice control, switch device or magnifier has tested Truehound for this report. All results come from automated rules, scripted keyboard checks and a developer's reading.
  • The report has not been audited by an independent accessibility firm.
  • 17 criteria are Not evaluated. They need a person to look: reading order, colour use, non-text contrast, text spacing, hover content, timing, motion, language of parts, pointer cancellation, and the consistency criteria.
  • The public pages have no visible skip link; a main landmark lets assistive technology jump past the header, and a sighted keyboard user has to Tab through it.
  • The signed-in product beyond the live demo pages listed above has not been evaluated, including the Truehound account pages and anything behind a connected workspace.
  • Our automated gate fails a build on serious and critical axe findings. Moderate and minor findings are not gated; none were found on the pages above on the report date.
  • Stripe's checkout and customer portal, GitHub, Google, Microsoft and the other sites Truehound links to are outside this report.

Fixed while preparing this report

  • Tables that scroll sideways on narrow screens could not be reached by keyboard (Trust Center, sub-processors, the sub-processor list document, the people table on Workspaces). They are now focusable regions with a name.
  • The header's Run a free scan button pushed the menu button off screen at 320 CSS pixels. It now shortens its visible label there and keeps the full name for assistive technology.
  • Long email addresses and file names in page headers and inline code overflowed the page on narrow screens. They now wrap.
  • A link on the AI page was told apart from the text around it by colour alone. It is now underlined.

Report a problem

If something on Truehound is hard to use with your assistive technology, write to truehoundhq@truehound.io with the page and what happened. We read every message and reply with what we will do. See also the Trust Center.

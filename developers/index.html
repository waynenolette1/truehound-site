The Truehound API

Who still has the keys: people, accounts, systems, findings, reviews, offboardings, evidence and the Proof chain.

Create an API keyOpenAPI 3.1 file

Keys and scopes

A key belongs to one workspace and carries scopes (people:read, config:write, ...). Only its hash is stored; it is shown once. Each operation below names the scope it needs.

Pages and errors

Lists answer { data, next_cursor }; pass next_cursor as cursor. Errors answer { ok: false, error, message } with the field or scope named in plain words.

Limits

600 requests a minute per key. Data is what your workspace last published from the app, so it matches what your team sees.

Webhooks

Truehound posts an event to your https endpoint when something changes, once per change. Every request is signed: the Truehound-Signature header is t=<unix seconds>,v1=<HMAC-SHA256 of t.body with your endpoint secret>. Answer 2xx within 10 seconds. Anything else is retried after 1 minute, 5 minutes, 30 minutes, 2 hours, 8 hours and 24 hours, and every attempt is in the delivery log, where you can send one again.

  • leaver.detectedSomeone left (HR or the identity provider says so) and still has access somewhere.
  • review.launchedAn access review was started: its population is frozen.
  • review.signedAn access review was signed off by a named reviewer.
  • review.endedA scheduled access review passed its due date and was ended by its schedule: undecided rows skipped or revoked (filed for approval), with the counts.
  • revoke.verifiedA removal was made and a re-read of the app proved the access is gone.
  • revoke.failedA removal was sent but the re-read still shows the access.
  • offboarding.startedAn offboarding run was started for a person.
  • offboarding.completedEvery step of an offboarding run is done.
  • finding.createdA new finding appeared (after the first publish).
  • finding.resolvedA finding is gone.
  • source.connectedA new system was connected.
  • proof.sealedAn event was sealed in the Proof chain.
  • access.requestedAn access request was filed (app, exact role, for whom, why, the approval route).
  • access.approvedAn approver approved an access request (with how many approvals the policy still needs).
  • access.deniedAn access request was denied, with the approver's reason.
  • access.grantedRequested access was granted (through the app's API and re-read, or by the owner's task).
  • access.revokedA grant was removed early or at its expiry, naming the exact app and role and whether a re-read proved it gone.
  • lifecycle.run_plannedA joiner, mover or offboarding run was opened with its steps; it waits for approval under the policy.
  • lifecycle.run_completedEvery step of a joiner, mover or offboarding run is done.
  • person.changedHR, SCIM or the API recorded a hire, a change or a termination.
  • pingA test event sent from the dashboard or POST /webhooks/{id}/test.

Check a signature (Node)

import crypto from "node:crypto";

// raw: the request body exactly as received (a string, before JSON.parse)
export function verifyTruehound(raw, header, secret, toleranceSec = 300) {
  const parts = Object.fromEntries(header.split(",").map((p) => p.split("=")));
  const expected = crypto.createHmac("sha256", secret).update(`${parts.t}.${raw}`).digest("hex");
  const fresh = Math.abs(Date.now() / 1000 - Number(parts.t)) <= toleranceSec;
  return fresh && crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(parts.v1 ?? ""));
}

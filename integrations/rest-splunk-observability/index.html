Read and fixed through the app's own API. Truehound removes access through the app's API after your approval, then reads the app again to prove it is gone.

What Truehound reads

Members and their roles, from Splunk Observability Cloud's API.

Not provided by Splunk Observability Cloud

  • Last sign-in: not provided by Splunk Observability Cloud's API.
  • Second factor: not provided by the API.

What it can fix

Remove a person from Splunk Observability Cloud through its API after your approval, then read Splunk Observability Cloud again to prove they are gone.

Set up

  1. 1An admin opens their profile (My Profile) in Splunk Observability Cloud and copies the User API Access Token, or creates an org access token under Settings > Access Tokens.
  2. 2Paste it here. It stays in this browser and is sent only to the app, through Truehound's relay.
Splunk Observability Cloud's own guide

Plans needed

  • Reading: Any Splunk Observability Cloud organization; member endpoints need a token of a user with the admin role
  • Removing: Any Splunk Observability Cloud organization; member endpoints need a token of a user with the admin role
  • Last login: not provided

Every connection

  • Read-only until you approve a change
  • Every change sealed in the Proof log
  • Apps not checked are listed as not checked
